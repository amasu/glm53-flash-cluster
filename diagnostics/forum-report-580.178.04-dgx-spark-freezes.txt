Title:
"Reproducible host-level hard-freezes on 2x DGX Spark after 7.6.0 OTA pushed
driver to 580.178.04 — NVRM kernel OOM bursts precede every hang; documented
Spark driver for 7.6.0 is 580.173.02"

--------------------------------------------------------------------------------
BODY
--------------------------------------------------------------------------------

Symptom
-------
Two DGX Spark (GB10) units, used as a RoCE-connected 2-node vLLM cluster, began
hard-freezing under normal serving load within ~24h of the DGX OS 7.6.0 OTA.
A "hard-freeze" here means: kernel still answers ICMP ping, but all userspace
goes unresponsive — sshd stops completing the banner exchange, no shell, no
recovery except physical power cycle. This happened 5+ times across the two
hosts on 2026-09-15/16, on two different serving stacks (both vLLM 0.28-based,
900K-context NVFP4 GLM-5.3-Flash; one with DFlash2 speculative decoding).

The same workload class on the same hardware was stable for weeks on
DGX OS 7.5.0 / driver 580.173.02 before the 7.6.0 OTA.

What the 7.6.0 OTA changed (apt/dpkg history, 2026-09-15 13:07, both nodes)
--------------------------------------------------------------------------
  DGX OS release:   7.5.0 -> 7.6.0
  Driver (open):    580.173.02 -> 580.178.04   (nvidia-driver-580-open:arm64)
  Boot kernel:      6.17.0-1032-nvidia -> 7.0.0-1019-nvidia
  Docker:           29.2.1 -> 29.6.2
  +180 packages total

Key discrepancy: the DGX OS 7.6.0 release notes document, for "ARM64 (DGX
Spark)", driver 580.173.02 (Canonical signed driver) and kernel
7.0.0-1018-nvidia. Our nodes received 580.178.04 — the datacenter-branch
build whose release-notes support matrix lists B300/B200/GB200/H100/L40/A100/
Quadro etc., with no mention of GB10, DGX Spark, or sm_121 — running on kernel
7.0.0-1019 (one point newer than the documented 7.0.0-1018). Web search turns
up no user reports for "580.178.04 DGX Spark"; the driver release is 2026-08-03
and the Spark-side rollout appears to have happened with the 7.6.0 ISO (2026-09-14).
